# RAG: smoke и оценка качества

RAG-слой находится в `src/rag/` и работает без внешнего сервиса: документы
режутся на перекрывающиеся чанки, индексируются гибридной моделью (детерминированные
вектора косинусного сходства + BM25 со стеммингом и стоп-словами) и ищутся
локально в памяти. Это позволяет проверять retrieval в CI без API ключей и
сетевых зависимостей.

## Быстрая проверка

```powershell
npm run rag-check
```

Smoke проверяет индексацию двух документов, поиск по смысловому запросу и
генерацию ответа с цитатой. Нулевой код означает, что pipeline отвечает и
возвращает релевантный чанк.

## CLI: сборка индекса и запросы

```powershell
# Собрать индекс кодовой базы и документации в .rag/index.json
npm run rag:build

# Задать вопрос к базе знаний (использует .rag/index.json по умолчанию)
npm run rag:query -- "как устроен снег"

# Фильтрация по типу источника (documentation / source) и ограничение top-K
npx tsx scripts/rag-cli.ts query --type documentation "погода и видимость"
npx tsx scripts/rag-cli.ts query --type source --top 3 "snow shader"
```

## Eval-набор

```powershell
# Оценка на встроенной тестовой фикстуре
npm run rag:eval
npx tsx scripts/rag-eval.ts docs/rag-eval.json

# Оценка на реальном собранном индексе репозитория
npx tsx scripts/rag-eval.ts docs/rag-eval.json --index .rag/index.json
```

`docs/rag-eval.json` содержит устойчивые проверяемые фразы, а не полные
эталонные ответы:

```json
[{"id":"controls","query":"Как управлять движением?","mustContain":["WASD"]}]
```

Результат выводится как JSON с `passRate`, количеством цитат и отсутствующими
фразами по каждому кейсу. Скрипт завершает работу с кодом 1, если хотя бы один
кейс не прошёл. Для регрессии добавляйте вопросы на границы чанков,
перефразирование и запросы без ответа; последний должен возвращать пустой список
`citations` и стандартное сообщение о нехватке сведений.


## Конфигурация и переменные окружения

`RagPipeline` принимает `chunkSize`, `chunkOverlap`, `embeddingDimensions`,
`topK` и `minScore` (значения по умолчанию находятся в
`src/rag/pipeline.ts`). Текущий smoke/eval запускается локально и не требует
переменных окружения или секретов. Если поверх pipeline появится HTTP-адаптер,
его URL и ключи следует передавать через окружение адаптера, не в fixture.

## Что измерять дальше

Для production-набора сохраняйте recall@k (нашёлся ли нужный документ),
долю ответов с цитатами и p95 задержки. Отдельно проверяйте дубликаты
`chunk.id`, пустые документы и обновление уже индексированного `documentId`.
