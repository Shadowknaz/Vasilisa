# Зона Отчуждения — PS1 Диорама

Интерактивная 3D-диорама в эстетике PlayStation 1: советский двор 108×108 с
четырьмя пятиэтажками, общей детской площадкой, ларьком, трансформаторной
подстанцией, улицей с двумя въездами и шагающим мехом «ВНИИТЭ-68». Мех
управляется в изометрическом режиме, пилот выходит из кабины и ходит от первого
лица. Пилот — героиня: в первом лице видны её рукава, варежки и сапоги под полой
тулупа (см. `docs/PLAYER.md`).

Проект декомпозирован из одного файла `index.html` на модули без изменения
поведения и визуального результата, а затем переведён на TypeScript (strict) и
собирается через Vite.

## Запуск

Проект использует npm, TypeScript и Vite. Three.js r128 подключается как
npm-зависимость `three@0.128.0` (`import * as THREE from 'three'`) — версия
движка не менялась.

```powershell
npm install        # установить зависимости (один раз)
npm run dev        # дев-сервер Vite: http://localhost:5173/
```

Прочие команды:

```powershell
npm run build      # tsc --noEmit + vite build (продакшн-бандл в dist/)
npm run preview    # локальный предпросмотр собранного бандла
npm run typecheck  # строгая проверка типов (tsc --noEmit)
npm run plan-check # прогон планировщика и валидатора без браузера (tsx)
npm run frame-stats -- --url http://localhost:5173/ --out .tmp-frame.png
                   # замер тона кадра, --keys q для облёта, --hold w:9000 чтобы дойти,
                   # --rect для пятна, --diff для стабильности
```

## Управление

| Действие | Клавиши |
| --- | --- |
| Движение меха / пилота | `WASD` или стрелки |
| Бег пилота | `Shift` |
| Выход из меха / посадка в мех | `E`, `F`, `Enter`, `Space` |
| Вход в подъезд и квартиры | пешком через проём, клавиши не нужны |
| Поворот изометрической камеры | `Q` / `R` (шаг 45°), перетаскивание мышью |
| Обзор всего острова | `O` (плавный переход и возврат) |
| Ночной шейдер вкл/выкл (тест) | `N` — кадр без ночной модели: нейтральный свет, без грейда, тумана и ламп |
| Обзор от первого лица | мышь (Pointer Lock) или перетаскивание |
| Мобильные устройства | 1 палец — обзор, 2 пальца — вход/выход из меха |

Посадка в мех разрешена только рядом с корпусом или у бронированной двери на
левом борту (см. `BOARDING`). Выход ищет свободную сторону в порядке «левый борт
(дверь) → перед → зад → правый борт» и требует место для шага в 1.2 м; если
свободных сторон нет, пилот остаётся в кабине.

В первом лице видно тело героини: рукава и варежки — в нижних углах кадра,
сапоги — при взгляде вниз, сквозь разрез тулупа. Шаг, покачивание полы и дыхание
рук идут от `pilotState.walkCycle` / `gait` (см. `docs/PLAYER.md`).

## Архитектура

Слои и направление зависимостей (сверху вниз — только в одну сторону):

```
main.ts                     композиционный корень
  ├── config/               константы: цвета, рендер, управление, геометрия
  ├── core/                 Three.js-примитивы: текстуры, материалы, сцена
  ├── world/                строители диорамы (здания, забор, теплотрасса...)
  ├── mech/                 строитель меха и его ног
  ├── player/               строитель героини: тело, тулуп, руки
  ├── state/                фабрики изменяемого состояния
  ├── systems/              логика кадра: ввод, коллизии, движение, камера
  └── render/               PS1-дисплей, постобработка, resize, цикл кадров
```

Ключевое правило: `world/` и `mech/` не знают о состоянии и вводе; `systems/`
не создают геометрию, а только изменяют состояние и трансформы готового рига.
Зависимости передаются явно через параметры (composition root — `main.ts`),
никаких скрытых глобальных синглтонов, кроме неизменяемых материалов/текстур.

### Слой плана и валидация

Мир 108×108 не собирается из литералов в строителях. Сначала считается и
проверяется план, и только потом строится геометрия:

```
roadGraph → surfaces (maskGrid) → objectDescriptors (footprints) → reservations
→ pedestrian → validateLayout → замороженный layout → world builders
```

- `createLayout()` (`src/world/layout/createLayout.ts`) собирает план, проверяет
  детерминизм (два прогона сериализуются побайтно одинаково) и замораживает его.
  `configHash` — FNV-1a по профилю из `src/config/layout.ts`.
- `validateLayout()` измеряет реальные футпринты и маски по правилам ТЗ §12
  (зазоры до дорог, зон и края мира, ширина подходов, проходимость меха,
  доступность 15 целей, детерминизм). Любая ошибка → `ok === false`.
- `main.ts` при `ok === false` показывает экран ошибки и **не строит сцену вообще**.
- Строители (`src/world/*.ts`) берут трансформ и параметры из `layout.objects`
  через `layoutObject()/objectsOfType()` и регистрируют коллайдеры вызовом
  `registerColliders(collision, object)` (`src/world/placement.ts`) — координаты и
  футпринты в строителях не задаются.
- `src/systems/collision.ts` — составные AABB (`addBox`) и `isFree(x, z, r)`:
  круг против прямоугольников плюс требование `|x| + r ≤ half − WALK_MARGIN`.

### Шагоход «ВНИИТЭ-68»

Мех собран из эталонной модели `mexa.html` и разложен по модулям без изменения
пропорций и палитры:

- **Корпус** (`mechHull.ts`): гироскопический приводной блок, ядро с
  фасеточными щеками, поясная накладка, спинной радиатор с рёбрами, сферы
  пневмоаккумуляторов и запасная бочка ГСМ. Рубка (`mechTower.ts`) несёт
  катодный визор с козырьком и дворником, жалюзи, трафарет «68», купол с
  перископом, оптический пост «Луноход», магнитную петлевую антенну и две
  «спутниковые» шпили.
- **Дверь** (`mechDoor.ts`): гермодверь на левом борту — рама, козырёк,
  штурвал-кремальера, ригели, поручень и складная подножка. Это и есть точка
  посадки: `BOARDING.HATCH_LOCAL` указывает на неё, а выход ищет свободное место
  сначала с левого борта.
- **Ноги** (`legs.ts`): hip-траверса с тремя гофропыльниками, коробчатое бедро с
  двумя гидроцилиндрами, колёсный барабан и утолщённая голень с амортизаторами
  и решётчатым отбойником, широкая лапа с грунтозацепами. Ноги крепятся к корню
  рига, а не к подвеске корпуса, поэтому при качке корпуса ступня остаётся
  стоять на покрытии.
- **Прожектор** (`mechSearchlight.ts`): корпус прожектора в решётке на правой
  щеке рубки, объёмные конусы, `SpotLight`, подсветка пятна касания и аддитивное
  пятно. Пятно живёт в отдельной мировой группе (см. раздел о слоях на земле).

Весь риг увеличен единым коэффициентом `MECH_RIG.SCALE` (1.3) прямо в
композиционном корне, поэтому пропорции эталона не меняются, а ступни остаются
на `y = 0`. Всё, что читается вне отмасштабированной группы, считается от того же
коэффициента: точка выхлопа (`config/mech.ts`), точки пыли под лапами, смещение
двери и клиренс пилота (`config/controls.ts`), радиус коллайдера, а также
смещение и размер светового пятна (`mechSearchlight.ts`). Замороженный профиль
плана (`MECH_PLAN`) не трогается: он задаёт консервативный конверт маршрутов и
от модели не зависит.

Походка (`systems/mechPose.ts`) — не «ходьба на месте», а движение под нагрузкой:

1. Фаза шага (`mechState.walkCycle`) растёт только когда мех действительно
   управляется; разворот идёт отдельно.
2. Ноги идут волной `FL → RR → FR → RL` со сдвигом в четверть цикла, поэтому в
   воздухе всегда одна диагональная пара: тяжёлая рысь, а не четырёхтактный шаг.
3. `mechState.gait` плавно поднимается до 1 при движении и спадает до 0 при
   остановке; амплитуда замаха и подъёма умножается на него, поэтому мех
   останавливается, ставя все четыре лапы, а не замирает в середине шага.
4. Корпус качается на подвеске (кивок, крен, дизельная вибрация), а лапы
   компенсируют наклон пятки: сумма углов бедра, колена и ступни равна нулю, так
   что подошва остаётся параллельна земле всю фазу.
5. Дверь дребезжит на каждом шаге, петлевая антенна идёт дискретными тиками,
   шпили качаются в такт — это единственные «механические» украшения, клапан
   выхлопа по-прежнему принадлежит `mechEffects.ts`.

Контактных теней у лап нет: проект сознательно живёт без теневых декалей (см.
`audit.md`), поэтому шаг читается по подъёму лапы и пыли из-под подошвы.

### Слои на земле и высота поверхности

Контактные тени-декали не используются: единственный плоский слой над
покрытием — аддитивное световое пятно прожектора (`groundLightPool`). Чтобы
пятно не мерцало относительно покрытий, действует одно правило:

1. **Одна высота на всё.** `createSurfaceField()` (`src/world/surfaceField.ts`)
   считает высоту рельефа и максимальную плиту под футпринтом (асфальт 0.02,
   плитка/тротуар 0.04, трафаретная площадка). Этим же полем выравнивается сама
   земля, поэтому меш рельефа и пятно не могут разойтись.
2. **Пятно живёт в world-группе.** `buildMech()` возвращает `ground.group`
   отдельно от рига: `applyMechPose()` каждый кадр пишет мировые `x/z` и
   поднимает плоскость на `maxHeightInRect(footprint) + GROUND_OVERLAY.GAP`.
   `rotation.x`/`y` лап, бедра и колена на пятно не передаются — поворот только
   вокруг Y.
3. **Глубина.** Материал пятна включает `polygonOffset`
   (`factor/units = −1`), `depthWrite: false` и фиксированный `renderOrder`;
   высота больше не «подбирается» числом 0.025–0.038.
4. **Без snap у плоских слоёв.** Snap — это экранный сдвиг вершин по `x/y` без
   `z`: две разные триангуляции одной плоскости сдвигаются по-разному и
   расходятся по глубине сильнее, чем зазор слоя. Поэтому земля, плиты, pad и
   само пятно создаются с `{ vertexSnap: false }`; объёмная геометрия snap
   сохраняет.
5. **Текстуры земли читаемы на своём масштабе.** Швы плит рисуются в два текселя:
   при 0,7 буферного пикселя на тексель однопиксельный шов существует только
   обрывками и «ползёт» при движении камеры. Мипмапы
   (`setGroundMinification()`) гасят шов на дальнем плане, анизотропия
   намеренно 1 — иначе шов снова под-сэмплируется вдоль луча зрения.
6. **Дизеринг не рисует шахматку.** Амплитуда Bayer-матрицы равна одному шагу
   квантования (`DITHER_WEIGHT = 1/8` при 7-битном шаге): больше — и на ровной
   земле появляется клетка из двух уровней, в которой каждая смена тона на
   пол-уровня переключает пиксели и «кипит».

Чёрные провалы (песочница, дверные и оконные проёмы, днища балконов и навесов) —
непрозрачная геометрия `innerVoidMat`/`undersideMat`, а не тени.

### Порядок обновления кадра

`updateSimulation()` в `src/systems/simulation.ts` сохраняет исходную
последовательность:

1. `time += dt`, обновление пула частиц.
2. Состояние «мех идёт» → клапан и дым выхлопа.
3. Режим `MECH`: закрытие люка, движение, пыль шагов.
4. Режим `FP`: открытие люка, пульс лампы, ходьба пилота.
5. Переходы `TRANSITION_TO_FP` / `TRANSITION_TO_MECH`.
6. Сглаживание изо-угла и бленда обзора, поза меха, затухание конусов
   прожектора от первого лица, камера, поза героини (руки уже знают позу
   камеры) и плотность тумана.
7. Эмиттеры прожектора из мировой матрицы пилона и один upload атмосферы
   (`updateAtmosphere`): туман, луна, полусферный ambient, массив ламп.
8. `frame.render()`: сцена в low-res render target, квад грейда, `drawImage`
   на 2D-canvas.

## Принципы декомпозиции

- **Single Responsibility.** Каждый модуль отвечает за один объект сцены, одну
  подсистему или один слой. `simulation.ts` только оркестрирует, `khrushchyovka.ts`
  только строит здание, `cameraRig.ts` только считает позу камеры.
- **DRY.** Общие значения вынесены в `config/`, общие материалы — в
  `core/materials.ts`, чтение клавиш — в `keyState.ts`,
  текстуры создаются одной фабрикой `createPixelTexture()`.
- **Без магических чисел.** Все настройки поведения (скорости, радиусы,
  чувствительность, тайминги, пороги постобработки) и общие размеры находятся
  в `src/config/`. Размеры деталей конкретной модели сгруппированы в
  именованные объекты-константы в начале соответствующего builder-модуля
  (`BUILDING`, `BALCONY`, `ROCKET`, `LEG`, `MECH`, ...), а не разбросаны по коду.
- **Без божественных объектов.** Нет единого `state`-объекта и единой
  «игровой» функции: состояние разделено на четыре фабрики, логика — на
  независимые системы, мир — на отдельные строители.
- **Одна точка сборки.** `main.ts` создаёт stage, мир, мех, состояние и системы
  и передаёт зависимости явно; сами модули не импортируют друг друга по кругу.

## Как расширять

- **Новый объект мира:** сначала опишите его в плане — футпринты и параметры в
  `src/world/layout/footprints.ts`, координаты и допуски в `src/config/layout.ts`,
  затем создайте `src/world/<name>.ts` с локальными константами и функцией
  `build<Name>(group, collision, layout)`, читающей размещения через
  `layoutObject()/objectsOfType()`, и вызовите её в `src/world/index.ts`.
  Новые правила проверки — в `src/world/layout/validateLayout.ts`.
- **Новый несолидный декор** (плоская разделка полотна, пятна, решётки) обязан
  получить политику в `DECOR_POLICY` (`validateLayout.ts`): `on-asphalt`,
  `on-paving`, `off-asphalt` или `off-routes`. Без политики правило
